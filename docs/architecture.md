# 项目架构与维护约定

本项目在一个仓库中维护学习内容、网页功能和开发工具。调整目录时，优先保持内容身份与用户数据兼容。

## 模块职责

| 目录 | 职责 | 依赖边界 |
| --- | --- | --- |
| `content/notes/` | Markdown 笔记及主题资源 | 不引用网页实现 |
| `content/exercises/` | 默认导出题目数组 | 仅通过类型引用 `contracts` |
| `content/catalog.ts` | 章节 ID、标题、描述、分组与顺序 | 不导入正文或题目，保持目录轻量 |
| `contracts/` | 跨环境的数据类型与存档格式校验 | 不依赖 Vue、DOM、Bun 或 Vite |
| `src/content/` | 目录查询、按需加载和章节链接 | 通过 Vite 加载内容，不执行文件写入 |
| `src/app/` | 布局、地址解析、加载状态和页面组装 | 组合功能模块，不承载题目数据 |
| `src/features/notes/` | 正文、目录、关系图与交互代码块 | 使用共享运行器，不依赖实验页面 |
| `src/features/exercises/` | 选题、编辑会话、答案与存档 | 使用共享运行器，不依赖笔记页面 |
| `src/shared/code-playground/` | 编辑、执行与输出、HTML 预览 | 不感知章节、题目和存档 |
| `tooling/` | Markdown 转换与本地存档写入 | 仅用于 Bun / Vite，不进入浏览器依赖图 |
| `scripts/` | 校验、回归测试和类型检查入口 | 可以访问多个模块以验证完整行为 |

只有已被多个功能使用的能力才放进 `shared`。新增功能先放到所属模块，不默认增加全局工具目录或依赖注入框架。

## 内容维护

笔记路径为 `content/notes/<id>/main.md`；实验路径为 `content/exercises/<id>.ts`。文件名与 `catalog.ts` 的 ID 对应。新增内容后，在目录中登记一次章节信息，执行 `bun run check-content`。

章节导航标题、分组、描述和顺序由目录统一管理。Markdown 一级标题用于正文展示；没有一级标题的既有笔记使用目录标题。不要从标题推导 ID。

配套图片放在主题自己的 `assets/` 中，用相对路径引用。Markdown 插件将资源转为 Vite 的 URL 导入，以适配开发、构建和基础路径。外链与页内锚点保持原样。章节之间使用应用地址链接；相对 `.md` 链接仅作为文件资源，不自动转为章节导航。

HTML 经过允许列表过滤后进入页面。关系图的允许类名在 `tooling/markdown/render.ts`，对应样式在 `src/features/notes/reference-diagrams.css`。修改图示能力时同步维护这两处。

## 加载与导航

目录在启动时加载，正文与题目通过 `src/content/repository.ts` 的动态导入按章节加载。页面只调用加载入口，不自行扫描文件。

`src/app/useChapterContent.ts` 管理加载、失败与重试。快速切换章节时取消旧请求的结果提交，避免较慢的旧章节覆盖当前选择。根地址打开首章；未知地址显示返回首章入口。

访问地址继续使用 `#/notes/<id>`、`#/lab/<id>` 和 `?section=<section-id>`。本次迁移保留既有标题编号形式的小节锚点；编辑笔记时增删前置标题仍可能影响后续小节编号，不应将其误认为永久稳定的语义锚点。

## 代码执行与练习状态

笔记和实验复用同一个运行器。每次 JavaScript 执行创建独立 Worker，保留原有超时、日志上限和线程回收行为。HTML 示例使用预览 iframe；两种执行环境的能力不同。

`useExerciseSession.ts` 管理选题、当前代码、答案和重置。重置仅影响编辑器，不删除已有存档；用户继续编辑后恢复自动保存。

实验页面按专题 ID 缓存，切换到笔记后可继续原来的练习。存档状态由全应用共享的 `editsState.ts` 管理，避免不同缓存页面分别持有过期数据并覆盖其他专题。

存储适配器 `editsStorage.ts` 处理读取、可写性探测和写入；状态模块负责延迟保存及串行提交。以后增加其他保存方式时实现 `EditsStorage` 接口，不修改运行器或题目数据。

## 兼容约定

- 章节 ID、专题 ID 与题目 ID 保持稳定，不因排序、标题或文件迁移而改变。
- 存档继续使用 `public/runner-edits.json`，保留版本 1 及 `edits[topicId][questionId]` 格式。
- 本地开发通过 `/__runner-edits` 写入文件；预览环境只读取。读取失败或格式不受支持时不覆盖原文件。
- 前端与本地保存服务共同使用 `contracts/edits.ts` 校验格式。后续修改格式时必须同时提供明确迁移方案。

## 验证方式

- `bun run check-content`：发现重复 ID、缺失文件、未注册内容、错误题目字段及缺失相对资源；不执行笔记代码或访问外部链接。
- `bun test`：验证 Markdown 过滤与挂载、运行器、地址解析、加载竞态、存档兼容、相对资源和 Vue 组件编译。
- `bun run type-check`：执行完整类型检查。
- `bun run build`：类型检查后生成生产构建。

后两项及开发服务由用户按需执行。组件编译测试不等于完整类型检查、生产构建或浏览器视觉验证。
