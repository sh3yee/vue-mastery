# Day 1 笔记：词法作用域、作用域链、执行上下文

## 一、核心总结

JavaScript 的变量查找机制可以用一句话概括：

> **函数执行时会创建执行上下文，执行上下文中包含词法环境，词法环境保存当前变量，并通过外部引用连接到外层词法环境，这条查找路线就是作用域链。**

简化理解：

```md
作用域：变量能不能被访问的规则
词法环境：保存变量的地方
作用域链：变量查找的路径
执行上下文栈：管理函数调用顺序
```

---

# 二、什么是词法作用域？

## 定义

**词法作用域，也叫静态作用域。**

它的意思是：

> **变量的查找范围在代码编写阶段就已经确定，取决于函数在哪里定义，而不是函数在哪里调用。**

JavaScript 使用的是 **词法作用域**，不是动态作用域。

---

## 示例

```js
let name = 'global'

function sayName() {
  console.log(name)
}

function run() {
  let name = 'run'
  sayName()
}

run()
```

输出结果：

```js
global
```

---

## 为什么输出 global？

因为 `sayName` 是在全局作用域中定义的。

所以它的外层作用域是全局作用域，而不是 `run` 函数作用域。

虽然 `sayName()` 是在 `run()` 里面调用的，但是变量查找不看调用位置，而是看定义位置。

所以：

```md
sayName 的作用域链：

sayName 当前作用域
  ↓
全局作用域
```

它不会去 `run` 函数里面找 `name`。

---

# 三、什么是作用域链？

## 定义

**作用域链就是变量查找时经过的一条链。**

当 JavaScript 查找一个变量时，会先从当前作用域找：

```md
当前作用域找
  ↓ 找不到
外层作用域找
  ↓ 找不到
再外层作用域找
  ↓
全局作用域找
  ↓ 找不到
报错
```

这条从内到外的查找路径，就叫 **作用域链**。

---

## 示例

```js
const a = 1

function foo() {
  const b = 2

  function bar() {
    const c = 3
    console.log(a, b, c)
  }

  bar()
}

foo()
```

当执行到：

```js
console.log(a, b, c)
```

变量查找过程是：

```md
找 c：
bar 作用域里有 c，直接找到。

找 b：
bar 作用域里没有 b，
去 foo 作用域找，
foo 里面有 b，找到。

找 a：
bar 作用域里没有 a，
foo 作用域里也没有 a，
去全局作用域找，
全局里面有 a，找到。
```

所以 `bar` 的作用域链是：

```md
bar 作用域
  ↓
foo 作用域
  ↓
全局作用域
```

---

# 四、词法环境和作用域链的关系

## 词法环境是什么？

**词法环境是 JavaScript 运行时保存变量的结构。**

可以简单理解成一个对象：

```js
{
  c: 3,
  outer: 外层词法环境
}
```

每个函数执行时，都会创建自己的词法环境。

词法环境里面保存：

```md
1. 当前函数里的变量
2. 当前函数里的函数声明
3. 当前函数的参数
4. 指向外层词法环境的引用 outer
```

---

## 作用域链怎么来的？

多个词法环境通过 `outer` 连接起来，就形成了作用域链。

例如：

```js
const a = 1

function foo() {
  const b = 2

  function bar() {
    const c = 3
    console.log(a, b, c)
  }

  bar()
}

foo()
```

对应的词法环境关系可以理解为：

```md
bar 词法环境
{
  c: 3,
  outer: foo 词法环境
}

foo 词法环境
{
  b: 2,
  bar: function,
  outer: 全局词法环境
}

全局词法环境
{
  a: 1,
  foo: function,
  outer: null
}
```

所以：

```md
作用域链 = 当前词法环境 + outer 指向的外层词法环境 + 再外层词法环境
```

一句话总结：

> **词法环境是一个个节点，作用域链是这些节点通过 outer 串起来形成的链。**

---

# 五、函数的作用域由定义位置决定，还是调用位置决定？

## 答案

**由定义位置决定。**

JavaScript 是词法作用域，所以函数的作用域在函数定义时就确定了。

---

## 经典例子

```js
let a = 'global'

function foo() {
  console.log(a)
}

function bar() {
  let a = 'bar'
  foo()
}

bar()
```

输出：

```js
global
```

---

## 原因

`foo` 是在全局作用域中定义的。

所以 `foo` 的外层作用域是全局作用域。

即使 `foo()` 是在 `bar()` 里面调用的，它也不会去 `bar` 里面找变量 `a`。

它的查找路线是：

```md
foo 当前作用域
  ↓
全局作用域
```

而不是：

```md
foo 当前作用域
  ↓
bar 作用域
  ↓
全局作用域
```

所以输出的是：

```js
global
```

---

## 如果是动态作用域会怎样？

如果 JavaScript 是动态作用域，那么变量查找会看函数在哪里调用。

上面的代码就会输出：

```js
bar
```

但是 JavaScript 不是动态作用域，所以实际输出是：

```js
global
```

---

# 六、为什么内部函数还能访问外部函数的变量？

## 答案

因为内部函数在定义时，会记住它所在的词法环境。

即使外部函数执行完了，只要内部函数还被外部引用着，外部函数的词法环境就不会被销毁。

这就是 **闭包**。

---

## 示例

```js
function outer() {
  let count = 0

  return function inner() {
    count++
    console.log(count)
  }
}

const fn = outer()

fn()
fn()
fn()
```

输出：

```js
1
2
3
```

---

## 为什么 `count` 没有消失？

正常情况下，`outer()` 执行完后，它的执行上下文会出栈。

但是 `outer()` 返回了内部函数 `inner`。

```js
const fn = outer()
```

此时 `fn` 引用了 `inner` 函数。

而 `inner` 函数在定义时，保存了对 `outer` 词法环境的引用。

所以 `outer` 里面的 `count` 仍然可以被访问。

可以理解为：

```md
全局变量 fn
  ↓
引用 inner 函数
  ↓
inner 函数引用 outer 执行时创建的词法环境
  ↓
outer 词法环境里保存着 count
```

所以每次执行 `fn()`，都还能访问并修改 `count`。

---

# 七、闭包和作用域链的关系

闭包的本质可以这样理解：

> **闭包就是函数保留了它定义时的作用域链。**

更具体地说：

```md
内部函数被外部引用后，
它仍然可以访问定义时所在的外部词法环境，
所以外部函数执行完后，
内部函数依然能访问外部函数的变量。
```

# 八、四个验收问题总结答案

## 1. 什么是词法作用域？

词法作用域就是：

> **变量的查找范围由函数定义位置决定，而不是函数调用位置决定。**

JavaScript 使用词法作用域。

---

## 2. 什么是作用域链？

作用域链就是：

> **变量查找时，从当前作用域开始，一层层向外层作用域查找，直到全局作用域的这条路径。**

作用域链本质上是由多个词法环境通过 `outer` 引用连接起来的。

---

## 3. 函数的作用域由定义位置决定，还是调用位置决定？

由 **定义位置** 决定。

因为 JavaScript 是词法作用域。

函数在哪里定义，它的外层作用域就在哪里确定。

---

## 4. 为什么内部函数还能访问外部函数的变量？

因为内部函数定义时会保存对外部词法环境的引用。

即使外部函数执行完，只要内部函数还被引用，外部函数的词法环境就不会被销毁。

这就是闭包。

# 九、总结

```md
作用域：
变量能访问的范围。

词法作用域：
变量查找看函数定义位置，不看调用位置。

词法环境：
代码执行时保存变量的地方。

作用域链：
多个词法环境通过 outer 串起来形成的变量查找路径。

执行上下文栈：
管理函数调用顺序，函数调用时入栈，执行完出栈。

闭包：
函数保留了它定义时的作用域链，所以内部函数可以继续访问外部函数的变量。
```
